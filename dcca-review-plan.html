DCCA Security & P1 Defect Review

Plan for a deep review of the DCCA sandbox codebase retrieved into force-app/ (16,415 files).

Early signals from a quick scan

135classes use without sharing
310classes declare no sharing
183classes build SOQL at runtime
60VF files use escape="false"
18files with hardcoded record IDs
~200files may run SOQL in loops
6profiles mention ModifyAllData

These are rough grep counts. Phase 3 checks them before anything is reported.

Review categories

#CategoryPriorityWhat gets checked
1SOQL/SOSL injectionP1Does user input reach runtime queries in the 183 classes without binding or escapeSingleQuotes?
2Sharing violationsP1Which without sharing or undeclared classes are reachable from @AuraEnabled, @RemoteAction, REST, or guest users?
3Missing CRUD/FLS checksP1Reads and writes without WITH USER_MODE, stripInaccessible, or Security.* checks
4XSSP1The 60 escape="false" usages, innerHTML in LWC, and missing encoding in VF
5Secrets and endpointsP1Hardcoded credentials or tokens, HTTP callouts, overly broad Remote Site and CSP entries
6Guest and community accessP1Guest-user profiles, public Experience Cloud pages, unauthenticated @AuraEnabled methods
7Over-privileged profilesP1ModifyAllData, ViewAllData, Author Apex, and Customize Application granted beyond admins
8Governor-limit defectsP1SOQL or DML inside loops, triggers that don't handle bulk records, recursion with no guard
9Trigger and Flow designP1/P2Several triggers per object, logic written in triggers, Flows competing with triggers
10Error handlingP2Empty catch blocks, swallowed exceptions, stack traces shown to users
11Hardcoded IDs and environment valuesP218 files with record IDs, plus hardcoded org URLs and usernames
